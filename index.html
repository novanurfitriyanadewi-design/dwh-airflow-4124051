Prasyarat Firebase (sekali saja)

  1. Buka Firebase Console → proyek Minggu 5/6 (atau buat baru) → Firestore Database → Create database (mode test).
  2. Project settings → salin Project ID dan Web API Key ke kolom di atas.
  3. Firestore → Rules (hanya untuk praktikum, batasi tanggal akhir): 
    rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /{document=**} { allow read, write: if request.time < timestamp.date(2026, 12, 31); }
  }
}
  4. Opsional – deploy file ini ke Firebase Hosting: npm i -g firebase-tools → firebase login → firebase init hosting (public = folder berisi index.html) → firebase deploy --only hosting.
Koleksi sistem yang dibuat otomatis: _pipeline (status gerbang), _obs_runs (riwayat observability), _catalog (katalog data), analytics_pr_N (sandbox sementara).

Setup – Bangkitkan Data Uji di Firestore

Tombol di bawah menghapus isi koleksi staging & dimensi lalu mengisinya dengan 30 pelanggan dan ±100 pesanan. Pilih skenario:

Belum ada aksi.

Cacat yang disuntikkan pada skenario "cacat"

  • 5 pesanan terduplikasi (order_id sama, dokumen berbeda – akibat retry)
  • 4 customer_id NULL, 3 customer_id yatim (C999)
  • 3 status REFUND di luar domain sah
  • 2 diskon melebihi total belanja, 2 nominal pencilan 99.999.999
  • 2 dokumen membawa kolom baru harga_total (schema drift)

Buka Firebase Console → Firestore dan buktikan sendiri bahwa seluruh dokumen berhasil tertulis ("status hijau") padahal isinya rusak.

Tests – Generic, Singular, dan Gaya Great Expectations

Tipe tersedia: unique, not_null, accepted_values, relationships, discount_lte_amount, range (min/max), zscore (pencilan statistik). Tambahkan baris JSON sendiri untuk kolom lain.

CI/CD – Gerbang Zero-Defect di Firestore

Simulasi satu Pull Request: salin staging ke sandbox analytics_pr_N → jalankan test → merge (promosi ke gold) hanya jika semua PASS → hapus sandbox (FinOps).

Menunggu pipeline.
Circuit breaker: gerbang menulis _pipeline/status. Dashboard menampilkan "Maintenance" bila status BLOCKED, bukan angka palsu.

Observability – 5 Pilar

Volume & distribusi dibandingkan dengan snapshot sebelumnya di _obs_runs. Jalankan berurutan: bersih → basi → cacat, lalu amati pilar yang berubah.
